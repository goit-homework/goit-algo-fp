# goit-algo-fp

Фінальний проєкт курсу "Алгоритми та структури даних". Сім задач,
що покривають структури даних, рекурсію, графи, жадібні алгоритми,
динамічне програмування та метод Монте-Карло.

## Структура

- `task1.py` — однозв'язний список (реверс, сортування злиттям, злиття двох)
- `task2.py` — фрактал "дерево Піфагора" через turtle
- `task3.py` — алгоритм Дейкстри з бінарною купою
- `task4.py` — візуалізація бінарної купи
- `task5.py` — обходи DFS і BFS з кольоровим градієнтом
- `task6.py` — задача про їжу: жадібний алгоритм vs DP (0/1 knapsack)
- `task7.py` — імовірності суми двох кубиків методом Монте-Карло
- `*.png` — згенеровані візуалізації

## Залежності

## Завдання 1 — однозв'язний список

Класична реалізація `LinkedList` з `Node`-вузлами. Три операції:

- **`reverse()`** — in-place, проходить список один раз, перенаправляючи
  посилання назад. O(n) часу, O(1) додаткової пам'яті.
- **`merge_sort()`** — рекурсивне сортування злиттям. Для linked list
  природніше за quicksort, бо не потребує доступу за індексом. O(n log n).
- **`merge_two_sorted(a, b)`** — об'єднує два відсортовані списки в один.
  Використовує внутрішню функцію `_merge_nodes`, та сама що в merge sort.

## Завдання 2 — дерево Піфагора

Рекурсивне розгалуження: кожна гілка ділиться на дві коротші під кутом
±45°, довжина множиться на `cos(45°) ≈ 0.707`. Користувач задає рівень
рекурсії (рекомендовано 6-10, на 12+ — перепит).

Колір гілки інтерполюється від темно-коричневого (стовбур) до зеленого
(листя) в залежності від глибини рекурсії. У вікні turtle працює зум
колесом миші, пан перетягуванням і вихід по клавіші `q`.

## Завдання 3 — алгоритм Дейкстри

Реалізація через `heapq`. Граф — умовна мережа з 16 українських міст
з вагами-відстанями. Складність: **O((V + E) log V)** завдяки бінарній
купі (без купи було б O(V²)).

Ключові деталі:

- купа містить пари `(відстань, вершина)`;
- стандартний lazy-delete трюк: якщо витягнули вершину з відстанню
  більшою за поточну найкращу — ігноруємо (це застарілий запис у купі);
- паралельно ведемо словник `previous[v]` щоб реконструювати самі шляхи.

Приклад виводу: найкоротший шлях Київ → Ужгород = 870 км
(Київ → Житомир → Львів → Ужгород). Червоні ребра на `dijkstra.png` —
дерево найкоротших шляхів.

## Завдання 4 — візуалізація бінарної купи

Базовий код з умови (`Node` з `uuid`, `add_edges`, `draw_tree`) — основа,
адаптована під побудову дерева з масиву купи. Зв'язок між масивом і
деревом: для індексу `i` діти знаходяться на `2i+1` (лівий) і `2i+2`
(правий).

Колір вузлів — градієнт по глибині: корінь темно-синій, листя
світло-блакитні. Це наочно показує що корінь — мінімум, а структура
розширюється "вниз і світліє".

## Завдання 5 — DFS і BFS

Обходи реалізовано **ітеративно**, як вимагає умова:

- **DFS через стек** (LIFO): кидаємо правого нащадка на стек першим,
  щоб лівого знімати наступним кроком. Результат для нашого дерева:
  `1, 2, 4, 8, 9, 5, 3, 6, 7` — preorder.
- **BFS через чергу** (FIFO, `collections.deque`): класичний level-order.
  Результат: `1, 2, 3, 4, 5, 6, 7, 8, 9`.

Кожен вузол отримує колір згідно порядку відвідування — від темно-синього
(перший) до світло-блакитного (останній). Інтерполяція в RGB між двома
точками. На `dfs.png` видно як обхід "пірнає в глибину", на `bfs.png` —
як він рухається рівнями.

## Завдання 6 — задача про їжу (0/1 knapsack)

Дві реалізації:

- **`greedy_algorithm`** — сортує страви за спаданням `calories/cost`
  і додає в кошик доки є місце. O(n log n).
- **`dynamic_programming`** — класичний 0/1 knapsack через 2D-таблицю
  `dp[i][b]`, рекурентність:
  `dp[i][b] = max(dp[i-1][b], dp[i-1][b-cost_i] + cal_i)`.
  O(n × budget) часу і пам'яті. Гарантовано оптимум.

Цікаве спостереження з прогону: для бюджетів 50 і 80 жадібний і DP
збігаються, але для 100 і 150 — DP дає на ~10% більше калорій. Причина:
жадібний фіксується на високих відношеннях calories/cost і "проходить
повз" варіантів, які менш ефективні поодинці, але разом дають кращий
результат.

| Бюджет | Greedy кал. | DP кал. | DP кращий |
|--------|-------------|---------|-----------|
|    50  |        670  |    670  |       —   |
|    80  |        870  |    870  |       —   |
|   100  |        870  |    970  |   +11.5%  |
|   150  |       1120  |   1220  |    +8.9%  |

## Завдання 7 — кубики Монте-Карло

Симуляція 1 000 000 кидків двох кубиків через `numpy.random` (векторизовано —
швидше за цикл Python). Підраховуємо частоту кожної суми (2-12), порівнюємо
з аналітичними ймовірностями.

### Результати

| сума | MC, %  | аналіт., % | відн. похибка |
|------|--------|------------|---------------|
|   2  | 2.78   | 2.78       | 0.18%         |
|   3  | 5.53   | 5.56       | 0.52%         |
|   4  | 8.32   | 8.33       | 0.14%         |
|   5  | 11.16  | 11.11      | 0.42%         |
|   6  | 13.91  | 13.89      | 0.15%         |
|   7  | 16.68  | 16.67      | 0.08%         |
|   8  | 13.91  | 13.89      | 0.18%         |
|   9  | 11.10  | 11.11      | 0.08%         |
|  10  | 8.32   | 8.33       | 0.20%         |
|  11  | 5.50   | 5.56       | 0.98%         |
|  12  | 2.79   | 2.78       | 0.36%         |

### Висновки

На мільйоні кидків середня відносна похибка склала **0.022%** —
експериментальні значення практично співпадають з аналітичними. Це
підтверджує закон великих чисел: при достатньо великому N емпіричні
частоти збігаються до теоретичних імовірностей.

Цікавий нюанс — найбільша похибка (0.98%) виявилась на сумі 11, тобто
на рідкісних значеннях. Це теж очікувано: рідкі події мають **відносно**
більший шум при тій самій кількості випробувань, бо абсолютне число
спостережень для них менше (5.56% від 1М = 55 600 кидків, а 2.78% =
лише 27 800).

Метод Монте-Карло — простий, надійний і легко вибудовується. Для задач
з відомим розподілом (як ця) він тільки підтверджує те що теорія вже
говорить. Реальна цінність MC — в задачах, де аналітика недоступна або
надто складна (комплексні стохастичні моделі, інтеграли у багатовимірних
просторах, симуляції черг тощо).

## Загальне резюме

Цей фінальний проєкт показав, як одні й ті самі базові структури даних
(списки, дерева, купи, графи) і базові підходи (рекурсія, ітерація з
стеком/чергою, жадібний, DP, Монте-Карло) застосовуються до різноманітних
задач. Жадібні алгоритми швидкі, але не завжди оптимальні. DP завжди дає
оптимум, але дорогий за пам'яттю/часом. Купа критична для ефективної
Дейкстри. Метод Монте-Карло — універсальний інструмент, коли аналітичні
методи буксують.
